# Security review

✅ One self-review of the whole repository, dated 2026-09-14 and checked against the code again on 2026-09-27 (`.github/workflows/dependencies.yml` runs the audits it relies on). The criteria are two current lists, versions pinned so that a later reader can tell whether they are out of date: the **OWASP Top 10:2025** (final; OWASP marks the 2021 edition superseded, and SSRF is no longer a category of its own but part of A01) and the **OWASP Top 10 for Large Language Model Applications, 2026 edition** (published 2026-08-04 by the OWASP GenAI Security Project; it replaces the 2025 edition) (both outside the repository). Why OWASP and not ISO 27001 or NIST: [decisions.md](decisions.md), 2026-09-14, *The security self-review follows OWASP*.

This file owns the **coverage**: what each item of the lists below was judged to be in this project. The findings themselves are GitHub issues labelled `security`. Every row below falls into one of three kinds — sound (with the grounds), an open finding (with the issue), or a gap (with the issue). There is no fourth kind. An advisory left installed on purpose, and a requirement left unmet on purpose, are listed under *Accepted risks*, at the end. The repository is public, so its `security` issues are too, with code locations and reproduction commands; a demonstration reachable from outside (`#41`, or the public site of M7) waits until they are closed or regraded.

## OWASP Top 10 for LLM Applications 2026

| Category | Verdict | Where |
| --- | --- | --- |
| LLM01:2026 Prompt Injection | 🔶 1 open finding | `#5` (indirect injection aimed at the **write decision**). **What exists**: every prompt that reads text the project did not write, excerpts, earlier turns (which an anonymous client sends itself, answers included), a link's anchor or a fetched page, holds it between `<quoted>` tags the text cannot forge, any URL left outside them is percent-encoded so it cannot close a marker, a block or its line (words it spells with `+` or `-` stay as readable as quoted text), and its system prompt says the quote is data, not instructions (`quote()`, `neutralize()`, `inert_url()` and `QUOTED_CLAUSE`, `rag/llm.py`; [decisions.md](decisions.md), 2026-10-08, *Text the project did not write enters every prompt as quoted material*). This is a **mitigation, not a guarantee**: a 4B model can obey a quoted instruction anyway, and a tag spelled with a letter that only looks like one of its own, the Cyrillic o (U+043E), which NFKC does not fold, is not caught. What it can do then is accepted, because the model has no tools, the context holds no secret, and the citation cards come from retrieval rather than from the generated prose (`frontend/src/features/chat/AnswerStream.tsx`), so the damage is confined to the accuracy of one answer's text, which a RAG assistant does not guarantee anyway. Every model decision that acts (route, gate, pick) is JSON validated by pydantic, with a deterministic fallback; there is no native tool calling; the deepening loop fetches at most 3 pages, chosen from the registry's link graph. |
| LLM02:2026 Sensitive Information Disclosure | 🔶 1 open finding | `#36`. **What is sound**: the index holds public campus pages and the course slides, both readable by every account, and no private per-user material, because upload **does not exist in the code** (no `FileField`, no endpoint). **What is missing**: once upload exists this row has to be judged again, which is an acceptance item of `#36`. The gates it will need have precedents: `LIVE_MAX_PDF_PAGES = 40`, the 120 s `document_timeout`, `artifact_name()` fixing the file name on disk |
| LLM03:2026 Excessive Agency | 🔶 gap | the deepening loop in `rag/agent.py` is constrained (a hard cap of 3 steps · explicit control flow · a pydantic-validated JSON decision at each step · ⛔ native tool calling · its one write, `decisions.jsonl`, is an audit artefact) but has **never been assessed against this category**, which rose from 6th to 3rd in 2026 → `#53` |
| LLM04:2026 Supply Chain | 🔶 1 open finding | `#10` (models not pinned to a revision). The dependency side is A03:2025, its accepted risks included. **What exists**: Python packages are pinned by `uv.lock` and installed with `--locked`; the models are named, not pinned to a revision. |
| LLM05:2026 Data and Model Poisoning | 🔶 2 open findings | `#5` — automatic growth is this project's poisoning surface; the mitigation decided on 2026-09-14 is a human confirmation step (`#48`; [decisions.md](decisions.md), 2026-09-14, *A person confirms what automatic growth proposes; the interface is graded*, point 1) · `#17` (in part: with no attribution on the shared index, a poisoned point reaches every account). **What exists**: every live write is tagged `ingest_source="live"` with its run id, so a run is rolled back in one call (`delete_by_run()`), and evaluation reads the crawl snapshot by default (the eval-isolation rule). |
| LLM06:2026 Unbounded Consumption | 🔶 2 open findings | `#8` (the size cap applies only once the whole response body is in memory) · `#12` (registration is open and the queue has no global cap). Numbered LLM10 in 2025. **What exists**: per-endpoint throttles (`ask` 4/min, `auth` 5/min, `config/settings.py`), questions of at most 1000 characters (`apps/qa/serializers.py`), a history window of 3 turns, an anonymous client's history bounded to the same 3 turns and 4000 characters per answer (`apps/qa/serializers.py`), one answer at a time, where a request that waits more than 90 s for the running one gets a 503 (`QUEUE_TIMEOUT_SECONDS`, `apps/qa/engine.py`), and a 30 s ceiling per LLM request. An anonymous caller is throttled by address at the `ask` rate, so the visitors behind one campus NAT share one budget of 4 a minute; that is the price of not rating anonymous callers lower, since a lower or daily limit per address would fall on exactly the students a NAT gathers, and the engine's 90 s queue is what bounds the load. A cap on all anonymous questions together is `#12`. |
| LLM07:2026 Misinformation | 🔶 gap | **What exists**: ⛔ generating and grading exercises (the most dangerous use is absent) · answers are generated only from retrieved excerpts · citation cards come from retrieval, not from the model's prose (`frontend/src/features/chat/AnswerStream.tsx` states the distinction) · the router refuses with a reason. **What is missing**: a verdict. `#20` measures average quality, not what a wrong deadline in one answer costs → `#56`. Numbered LLM09 in 2025 |
| LLM08:2026 Hidden Context Exposure | 🔶 gap | 2026 widens 2025's "System Prompt Leakage" to any content assembled into the model's context that the user does not see, retrieved text, tool schemas and process rules included; this project's context holds all three → `#54`. **What exists**: the prompts hold no secret or credential, and the router sees only the student's questions, never the answers. |
| LLM09:2026 Vector and Embedding Weaknesses | 🔶 1 open finding | `#17` (a shared index where no point records who caused it). `#17` was first classed under LLM04 Data and Model Poisoning (LLM05 in 2026), which names the consequence; isolation and provenance in a shared vector store are this category. **What exists**: every web point carries its provenance (`ingest_run_id`, `ingest_source`, `trigger`), so a run can be found and rolled back; what is missing is who caused a live write. |
| LLM10:2026 Improper Output Handling | ✅ sound | one validation point for the LLM's JSON output, a deterministic safe fallback at each caller, a 30 s timeout (`rag/llm.py`); rendering on the frontend is A05:2025. Numbered LLM05 in 2025 |

## ASVS 5.0: V6 Authentication and V7 Session Management

The two lists above name categories. Signing in and sessions have requirements of their own in the **OWASP Application Security Verification Standard 5.0.0**, chapters V6 and V7 (outside the repository), checked here against the code on 2026-10-28: the requirements of levels 1 and 2, the levels for a site that holds accounts; level 3 is not judged. The rows are of the same three kinds. The site proves who someone is by a password alone, through two doors: the page's `POST /api/auth/login` ([api.md](api.md)) and `/admin/login/`, which admits superusers only (`config/admin.py`); with `DEBUG` on, DRF's `BasicAuthentication` is a third.
